## Checklist

### 1. Tokens not logged — PASS

Production Copilot/Windsurf paths never format `access_token`, `oauth_token`, or `api_key` into logs.

| Location | Evidence |
|---|---|
| `src-tauri/src/import/copilot.rs:36-38` | Comment + parser: walks JSON for `oauth_token`; does not log it |
| `src-tauri/src/windsurf_local.rs:1,72-79,82-96` | Module contract “never log token values”; `WindsurfLocalError` Display is path/class only (`OpenFailed`, `TokenMissing`, `IdentityUnderivable`) |
| `src-tauri/src/menu_actions.rs:134-143,223-247` | Import success saves credentials; failure `eprintln!("import: {e}")` uses provider error strings, not `ImportedAccount`/`Credentials` Debug. `record_add_outcome` logs store reason literals/paths only |
| `src-tauri/src/poller/mod.rs:10` | Poller contract: never log/print credential values |
| `src-tauri/src/api.rs:11-12,188-235` | Local API is GET/read-only; `AccountUsageDto` projects id/provider/auth_kind/display_name/plan/status/quotas — no `auth_source`, `credential_id`, `database_path`, or tokens |
| `src-tauri/src/api_accounts.rs:12-25` | Inventory label is `windsurf_database` / `browser_oauth`, never a secret |

Copilot/Windsurf `eprintln!` sites (`import:`, `import: failed to save account`, dispatch refusals) cannot embed the token: Copilot missing-file error is a fixed string (`import/copilot.rs:8`); Windsurf errors are the Display variants above.

### 2. sqlite OpenFlags read-only — PASS

Production Windsurf open is read-only:

```102:103:src-tauri/src/windsurf_local.rs
    let conn = Connection::open_with_flags(path, OpenFlags::SQLITE_OPEN_READ_ONLY)
        .map_err(|e| WindsurfLocalError::OpenFailed(e.to_string()))?;
```

`SQLITE_OPEN_URI` is not set, so the stored filesystem path is not reinterpreted as a SQLite URI (`file:...?mode=rwc`). The only other `OpenFlags` production open is Cursor (`cursor_local.rs`), same flag. Test helpers use `Connection::open` + `INSERT` against tempfile DBs only (`windsurf_local.rs:158-171`, `import_tests.rs:678-697`).

### 3. No DB writes — PASS

Production SQL in `windsurf_local.rs` is a single parameterized `SELECT value FROM ItemTable WHERE key = ?1 LIMIT 1` (`read_item`, lines 13-25). No `INSERT`/`UPDATE`/`DELETE`/`execute` outside `#[cfg(test)]`. Poller re-reads the session each cycle and keeps the key in memory (`providers_pro.rs:351-399`); `add_with` for Windsurf stores a **reference** (`AuthSource::WindsurfDatabase { database_path, expected_identity }`), not the apiKey (`store/mutations.rs:217-230`).

### 4. Windsurf identity is not the raw apiKey — PASS

Identity derivation (`windsurf_local.rs:56-70`):

1. lowercase `email`
2. else `userId` / `user_id` / `id`
3. else lowercase trimmed `name`
4. else SHA-256 fingerprint `key:` + first 8 digest bytes (hex), **not** the key

Test `fingerprints_key_when_no_identity_fields` asserts `identity.starts_with("key:")` and `identity != "only-key"`. That fingerprint is what `expected_identity` persists in `accounts-v2.json`. Typical `windsurfAuthStatus` shape is `{ "apiKey": "sk-ws-01-..." }` plus optional email/name — the no-identity path is the common case and is hashed.

### 5. Copilot token not sent to non-GitHub hosts — PASS

`fetch_copilot_user` (`poller/http.rs:323-364`) builds one request via `copilot_request`:

- URL const `https://api.github.com/copilot_internal/user`
- `Authorization: token …`, retry same URL as `Bearer …` on HTTP 401
- No other Copilot HTTP helper; `poll_copilot` only calls this fetcher (`providers_pro.rs:328-348`)

`gh` `hosts.yml` import is scoped to the `github.com` section (`import/copilot.rs:52-84`, `eq_ignore_ascii_case("github.com")`). reqwest 0.12 (`src-tauri/Cargo.toml`) follows redirects but strips `Authorization` on cross-origin hops; the dest URL is still the github.com constant.

### 8. User-Agent not spoofing `GitHubCopilotChat` — PASS

Repo-wide: **zero** matches for `GitHubCopilotChat`. Copilot request sets `User-Agent: UsageCheck` (`USAGECHECK_UA`, `http.rs:239,337`). GitHub’s required editor headers are separate: `Editor-Version: vscode/1.98.1`, `Editor-Plugin-Version: copilot-chat/0.26.7` — not the User-Agent product token. Windsurf also uses `UsageCheck`.

### 9. No `GITHUB_TOKEN` env silent import — PASS

`load_copilot_cli_auth` reads only local files (`paths::github_copilot_token_files()` = `apps.json`/`hosts.json` under the config `github-copilot` dir; `gh_hosts_yml_files()` = `gh/hosts.yml`). Comment at `import/copilot.rs:126-131`: “Does not read `GITHUB_TOKEN`”.

Workspace grep for `GITHUB_TOKEN`: that comment and `docs/editions.md:224-225` only. No `std::env::var("GITHUB_TOKEN")` (or similar) in Rust/Swift/TS. Missing-files import fails closed with the Copilot-specific error (`import_tests.rs:672-675`) and does not consult the environment. A CI `GITHUB_TOKEN` inherited by a desktop process is therefore not imported.

## Residual (not scored as vulns)

1. **`#[derive(Debug)]` on secret-bearing structs** (`WindsurfSession.api_key`, `Credentials.access_token`, `ImportedAccount`). Production Copilot/Windsurf code does not print them; a future `{:?}` log would leak. Same pre-existing pattern as Cursor.
2. **Copilot `apps.json` walker is not host-scoped.** `parse_copilot_oauth_token` returns the first nested `oauth_token`. `hosts.yml` is correctly limited to `github.com`. A GitHub Enterprise-only `apps.json` could import a GHE token and send it to `api.github.com`. Still a GitHub host; typical Copilot file is `github.com:device`.
3. **Identity vs apiKey equality is not explicitly rejected.** If a nested `id`/`name`/`email` ever equaled the apiKey, that string would be stored as `expected_identity`. Observed `windsurfAuthStatus` is `apiKey` ± email/name; the empty-identity path fingerprints. Smallest hardening: skip identity candidates equal to `api_key`.

None of these is a reachable high/critical issue in the shipped paths above.
