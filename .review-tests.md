## 6. SQLite read-only — 7/10

**Implementation is correct; the contract is not test-locked.**

`src-tauri/src/windsurf_local.rs` `read_windsurf_session`:

```rust
Connection::open_with_flags(path, OpenFlags::SQLITE_OPEN_READ_ONLY)
```

Same flag in `src-tauri/src/cursor_local.rs`. Import and poll both call `read_windsurf_session`. Tests (`reads_api_key_and_email_identity`, `accepts_nested_api_key`, `windsurf_import_reads_sqlite_api_key`) go through that function, so they **read** via the production opener.

They do **not** prove the open is read-only:

- Fixtures are created with writable `Connection::open`, then read. Replacing `open_with_flags(..., SQLITE_OPEN_READ_ONLY)` with `Connection::open` would still pass every test.
- No chmod-0444 / immutable-file read.
- No INSERT/UPDATE on the session connection expecting `SQLITE_READONLY`.
- No `OpenFailed` test for a missing path.

Smallest required test: after writing the fixture, `chmod 0o444` the `.vscdb` (unix) and assert `read_windsurf_session` still succeeds. A read-write `Connection::open` typically fails when SQLite cannot create a journal.
