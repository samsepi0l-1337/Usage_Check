# Review: PR #32 — Pro-gated Experimental GitHub Copilot and Windsurf

SHA: `04af78f8454fc4018d21d03d03f34ec10e884612`

Pro gating, tray Experimental labels, Copilot 401/403/404 mapping, no `GITHUB_TOKEN` primary import, Windsurf read-only SQLite, `AuthSource::WindsurfDatabase`, and no Codeium provider are in place. Two poll/import defects keep this below mergeable.

---

bug: Windsurf `GetUserStatus` parser never reads the live Connect JSON shape, so daily/weekly used % stay empty on a 200.

Status: fixed
Response: Parser now walks `userStatus.planStatus.*` (and snake_case), including `planInfo.planName` and string `overageBalanceMicros`. Fixture test covers the live nested JSON. A 2xx with no five_hour and no week is `experimental_error`, so last-success is not overwritten with empty windows.

`parse_windsurf_user_status` only walks root-level or one-level paths (`planStatus.dailyQuotaRemainingPercent`, `userStatus.dailyQuotaRemainingPercent`, `quota.*`). The same `SeatManagementService/GetUserStatus` payload this repo already handles for Agy is nested:

```json
{ "userStatus": { "planStatus": { "planInfo": { "planName": "…" }, "dailyQuotaRemainingPercent": 80, "weeklyQuotaRemainingPercent": 55, "overageBalanceMicros": "964220000" } } }
```

Agy unwraps that wrapper in `parse_agy_user_status` (`crates/usage-core/src/fetch/agy.rs:203-220`). Windsurf does not (`crates/usage-core/src/fetch/windsurf.rs:111-136`). Tests only cover the flattened fixture (`windsurf.rs:153-171`), so they cannot catch this.

On a successful HTTP parse-miss, `poll_windsurf` still reports `"ok"` (`src-tauri/src/poller/providers_pro.rs:380-392`) instead of `experimental_error` / `waiting_for_usage`. `apply_last_success` then **overwrites** the last good snapshot with empty windows (`src-tauri/src/poller/last_success.rs:38-50`).

Smallest fix: add `userStatus.planStatus.*` / `user_status.plan_status.*` (and `planInfo.planName`) to the path lists; treat a 2xx with no `five_hour` and no `week` as `experimental_error` (or `waiting_for_usage`) so empty parses cannot cache as success. Optionally map `dailyQuotaResetAtUnix` / `weeklyQuotaResetAtUnix` onto `resets_at`.

bug: Windsurf URL fallback clobbers a 401/403 from the primary host.

Status: fixed
Response: `fetch_windsurf_status` returns immediately on 401/403 (and other non-fallback codes). The Codeium host is tried only on 404, 5xx, or transport failure.

`fetch_windsurf_status` continues on every non-success and returns only `last_status` (`src-tauri/src/poller/http.rs:381-402`). Kimi’s sibling fallback returns immediately on 401 and only continues on 404 (`http.rs:272-278`). A 401 from `server.self-serve.windsurf.com` followed by a 404/500 from `server.codeium.com` becomes `experimental_error` instead of `needs_login` (`providers_pro.rs:312-325`).

Smallest fix: on 401/403 return immediately; continue only for 404/5xx/transport.

bug: Copilot local import never looks at the Windows token directory.

Status: fixed
Response: Windows import also reads `%LOCALAPPDATA%/github-copilot/{apps.json,hosts.json}` (apps first) after the existing XDG/`~/.config` paths. `gh` hosts.yml fallback is unchanged.

`github_copilot_token_files` is XDG / `~/.config/github-copilot/{apps,hosts}.json` only (`src-tauri/src/paths.rs:239-246`). The same file already special-cases Windows `gh` as `%APPDATA%/GitHub CLI/hosts.yml` (`paths.rs:254-259`). Copilot IDE tokens on Windows live at `%LOCALAPPDATA%/github-copilot/apps.json` (and `hosts.json`). A Windows user signed into Copilot but not `gh` fails import even though the files exist.

Smallest fix: on Windows also push `LOCALAPPDATA/github-copilot/{apps,hosts}.json` (apps.json first), keeping the gh hosts.yml fallback.

suggestion: Windsurf identity DFS can latch onto a nested generic `id`.

Status: fixed
Response: Identity is email (DFS), then `userId`/`user_id` on the auth-status object only, then name at root, then key fingerprint. Bare nested `id` is ignored.

`identity_from_status` searches `email`, then `userId`/`user_id`/`id` anywhere in the JSON (`src-tauri/src/windsurf_local.rs:62-69`). A rotating session/device `id` would flip `expected_identity` and yield `identity_changed` on the next poll. Prefer email, then `userId`/`user_id` at the auth-status object only, then the key fingerprint; do not walk a bare `id`.
